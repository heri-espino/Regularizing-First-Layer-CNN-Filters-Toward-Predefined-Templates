# AI handoff

## Machine / permissions constraints

The user frequently runs this repository on university-managed Windows machines without administrator privileges. Treat the working tree as potentially **partially non-writable** even when Git itself can modify existing files and create commits.

Observed behavior on 2026-09-18:

- existing tracked files can be edited and committed;
- Git can write to `.git/` and push normally;
- creating a new directory such as `analysis/metric_sensitivity_001/` from PowerShell can fail with `UnauthorizedAccessException`;
- experiment outputs under `%LOCALAPPDATA%\prior-templates-cnns\results\...` are writable;
- therefore `git add .` does **not** capture experiment outputs stored in `%LOCALAPPDATA%`.

Do not tell the user to rerun a completed experiment merely because its outputs were written outside the repository or because a paper-facing directory cannot be created in the worktree.

## Required workflow for experiment outputs

Before launching a long experiment on Windows:

1. Verify and record the output root.
2. Prefer a user-writable external location such as
   `%LOCALAPPDATA%\prior-templates-cnns\results\<study>`.
3. Keep raw/checkpoint-heavy outputs there.
4. After completion, archive only the paper-facing analysis products and provenance required by the study.
5. If the worktree refuses creation of new directories, stage external files directly into the Git index with the repository helper rather than copying them into the worktree.

For the metric-sensitivity study use:

```powershell
.\run\stage_metric_sensitivity_results.ps1
git status
git commit -m "analysis: add metric sensitivity results"
git push
```

The staging helper uses `git hash-object -w` plus `git update-index --cacheinfo`, so it can add files from `%LOCALAPPDATA%` without creating the destination directory in the worktree. It also marks those index entries `skip-worktree` locally after staging so the university ACL does not immediately appear as unstaged deletions.

On a normal writable clone the committed files will materialize normally.
