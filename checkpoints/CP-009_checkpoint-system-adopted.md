# CP-009 — Append-only checkpoint system adopted

**Date:** 2026-09-21  
**Status:** documentation/process implementation complete  
**Evidential role:** implementation-only  
**Contemporaneous:** yes

## Why this checkpoint exists

The repository had extensive protocols, analyses, manuscript notes, and handoff documentation, but no single chronological log that preserved the reasoning behind each implementation and result.

That made it possible for a future agent to understand *what files exist* while still losing *why a decision was made, what was known at the time, and what was supposed to happen next*.

## Engineering objective

Introduce an append-only checkpoint system that preserves research state over time and becomes mandatory whenever new implementations or results appear.

## What was done

Created the root-level `checkpoints/` directory with:

- `README.md`: checkpoint policy and naming rules;
- `TEMPLATE.md`: required structure for future checkpoints;
- `CP-001` through `CP-008`: retrospective reconstruction of the project history and current pre-submission state;
- this `CP-009`: first contemporaneous checkpoint under the new policy.

The checkpoint format records:

- why work was done;
- scientific/engineering objective;
- implementation;
- evidence/results;
- interpretation;
- limitations;
- provenance;
- next actions;
- constraints that must not be forgotten.

## Evidence or results available now

No new scientific outcomes were generated by this implementation.

This checkpoint concerns research-process integrity only.

## Interpretation

The repository now has three complementary memory layers:

1. **`RESEARCH_STATUS.md`** — current state;
2. **`.ai_handoff`** — operational rules for the next agent;
3. **`checkpoints/`** — append-only chronological history.

Frozen protocols and archived analyses remain authoritative for exact study design and numerical results.

## What this does not establish

- Checkpoints do not replace frozen protocols.
- Checkpoints do not replace analysis reports.
- A checkpoint summary is not itself scientific evidence.
- Historical checkpoints CP-001--CP-008 are retrospective reconstructions, not contemporaneous preregistrations.

- Never rewrite an older checkpoint to match later outcomes.
- Update `checkpoints/README.md` so its “current latest checkpoint” line points to the newest ID.
- Determine the next ID by inspecting the directory, not from memory.
