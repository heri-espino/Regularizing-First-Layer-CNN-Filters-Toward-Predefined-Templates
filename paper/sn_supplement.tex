\section{Architecture and training specification}\label{supp:architecture-training}

For each task and renderer block, the data generator draws 128 training, 64 validation, and 64 test contexts from independent deterministic streams. Each context specifies rendering conditions such as angle, scale, and noise. Rendering all four classes in every context gives 512/256/256 images in the three splits. Models are trained for 200 epochs with Adam, learning rate 0.003 and batch size 128. Retention keeps the first-layer penalty at $\lambda=1$ throughout training. Release uses the same penalty through epoch 10, decreases it linearly to zero at epoch 80, and leaves it at zero thereafter. In the architecture study, paired retention and release runs use the same model initialization and paired minibatch-order streams. Pairing is within each renderer block, task, architecture, and initialization replicate.

All architectures use a bias-free $1\!\to\!16$, $9\times9$ first convolution with same padding and ReLU. Patching is applied to the post-ReLU output of this layer. GMP and GAP denote global max and global average pooling. Plain depth-2 models add one downstream $3\times3$ convolution; plain depth-4 models add three. Width-64 variants expand the first downstream convolution from 16 to 64 channels and remain width 64 thereafter. Residual depth-4 models remain width 16 and add the third downstream convolution to the original first-layer activation before the final ReLU. BatchNorm, when present, occurs only after the patching location, following each downstream convolution. A learned linear classifier maps the pooled representation to four classes.

\section{Intervention-size and metric robustness}\label{supp:intervention-size}

For a patching metric $M$, the main intervention-size contrast is
\begin{equation}
B^M=
\frac{\Delta^M(4)+\Delta^M(8)}{2}
-
\frac{\Delta^M(1)+\Delta^M(2)}{2},
\end{equation}
where $\Delta^M(k)$ is release minus retention at intervention size $k$. The initial pre-specified test uses 20 held-out renderer blocks and the primary \texttt{two\_concepts}/TinyCNN setting.

\section{Pixel-permuted spatial control}\label{supp:spatial}

The spatial-control experiment compares the original structured filter bank with a bank obtained by applying one common permutation to the 81 spatial coordinates of every filter. This transformation preserves row norms, the complete Gram matrix, numerical rank, singular values, and the coefficients in each filter, including how often each value occurs. It destroys the original two-dimensional arrangement. The primary analysis uses 100 new renderer blocks and four architectures.

\section{Reconstructing joint outputs from individual patches}\label{supp:additivity}

We re-evaluate saved checkpoints by patching one first-layer channel at a time. We then reconstruct the jointly patched output by summing these individual centered-logit changes against the same base run. We evaluate all $k=0,\ldots,16$ and use $k=1,2,4,8$ to compute $B$. The protocol, implementation manifest, numerical unit tests, and analysis code are included in the accompanying archive's additivity study group (see the source-path manifest for original identifiers).

\section{Integrity checks and artifact scope}\label{supp:integrity}

Full-patch and no-op identity checks are recorded in the archived evaluator summaries. For the analytic Tiny controls, observed and reconstructed centered-logit curves agree to floating-point precision. An independent checkpoint reimplementation audit of the earlier causal evaluator is included in the archive's checkpoint-audit data group.

The reproducibility archive excludes raw training checkpoints and per-model evaluator JSON files, which are retained separately because of their size. Its derived tables support regeneration of the five manuscript figures and selected independent numerical checks. The other reported inferential summaries remain archived, rather than being recalculated by the compact entry point. The separately supplied manuscript-source ZIP includes LaTeX, the bibliography, required figures, and figure inputs. The original-to-exported file map and limitations are documented in the archive README and manifest.
